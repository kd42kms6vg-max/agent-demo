# mini-agent — 零框架搭建 Function Calling Agent

一个不到 300 行的 Node.js 项目，**不依赖任何 Agent 框架**，基于阿里云百炼 qwen-plus 的 OpenAI 兼容接口，搭建 Function Calling 的完整 Agent Loop。

工具定义规范参考：[QwenLM/Qwen-Agent](https://github.com/QwenLM/Qwen-Agent)（阿里官方 Agent 框架）。

## 它解决什么问题

大模型本身只会"说话"，让它能"做事"（查天气、算数、查知识库），需要一套工具调用机制：

```
用户提问
   ↓
┌──────────── Agent Loop ────────────┐
│ 模型判断：直接回答 or 调用工具？        │
│  ├─ 调用工具 → 执行 → 结果喂回模型 ──┐ │
│  │              ↑__________________| │
│  └─ 直接回答 → 输出最终答案           │
└────────────────────────────────────┘
```

## 内置 4 个工具

| 工具 | 说明 | 数据源 |
|---|---|---|
| get_current_time | 当前时间 | 系统时钟 |
| calculate | 四则运算 | 白名单校验 + 受控求值（防注入）|
| get_current_weather | 实时天气 | Open-Meteo 免费 API（真实数据）|
| search_knowledge_base | 公司制度检索 | 本地 JSON 知识库（RAG 检索最小演示）|

## 运行

```bash
# 1. 配置 Key：把 .env.example 复制为 .env，填入你的 DASHSCOPE_API_KEY
# 2. 运行（Node 18+，零 npm 依赖，无需 npm install）
node agent.js
```

试试这些问题，观察模型的「决策过程」：

- 「现在几点？」→ 调用时间工具
- 「345 * 23 等于多少？」→ 调用计算器
- 「深圳今天适合穿什么？」→ 调用天气工具 + 结合常识回答
- 「公司年假怎么请？」→ 调用知识库检索
- 「对比北京和深圳现在的温度」→ **一次规划，连续两次工具调用**

## 设计要点

1. **为什么不套框架？** Agent Loop 的核心只有约 20 行：模型返回 `tool_calls` 就执行工具、把结果以 `role:'tool'` 消息回传、循环直到模型给出文本回答。自己搭一遍，才能理解 LangChain / Qwen-Agent 这类框架到底帮你省掉了什么。
2. **工具执行失败怎么办？** 失败信息同样回传给模型（而不是抛到顶层崩溃），由模型决定重试、换工具还是向用户澄清。
3. **如何防止计算器被注入恶意代码？** 白名单正则校验表达式字符 + 受控求值，非法输入直接拒绝。
4. **如何防止无限循环？** 设置 `MAX_TOOL_ROUNDS` 上限，超过即终止并提示用户。
5. **`tool_call_id` 是干什么用的？** 模型一次可以要求调用多个工具，回传结果时靠这个 ID 一一配对，错位会导致模型混淆。
